# МИН — самостоятельный мессенджер в KONTUR Web

`МИН` — пародия на MAX с названием, построенным на противоположности `MAX ↔ MIN`.

## Что уже работает

Клиент не использует игровое сохранение, день недели, игровые часы или scripted-ответы. Его данные хранятся отдельно:

```text
localStorage: until-friday-min-messenger-v1
IndexedDB: until-friday-min-media-v1
BroadcastChannel: until-friday-min-sync-v1
```

Реализовано:

- произвольная отправка сообщений;
- личные чаты;
- группы;
- каналы;
- избранное;
- контакты;
- папки чатов;
- непрочитанные сообщения;
- черновики;
- ответы;
- пересылка;
- редактирование;
- удаление;
- реакции;
- закрепление сообщений и чатов;
- архив и отключение уведомлений;
- поиск по чатам, сообщениям и контактам;
- изображения, видео, аудио и обычные файлы через IndexedDB;
- запись голосового сообщения через MediaRecorder;
- локальная проверка камеры и микрофона;
- экспорт и импорт резервной копии;
- синхронизация состояния между вкладками одного браузера;
- независимый профиль и настройки.

## Почему GitHub Pages недостаточно для общения между людьми

GitHub Pages раздаёт только статические HTML, CSS и JavaScript. Он не может:

- регистрировать и авторизовывать пользователей;
- хранить серверную историю сообщений;
- доставлять сообщения другому устройству;
- хранить файлы пользователей;
- отправлять push-уведомления;
- быть сигнальным сервером WebRTC-звонков;
- проверять права администраторов групп и каналов.

Поле `Адрес сервера` в настройках зарезервировано для отдельного backend. До его подключения МИН работает в local-first режиме и не притворяется сетевым сервисом.

## Требования к будущему backend

Сетевой сервер должен предоставить:

1. регистрацию, вход и управление сессиями;
2. пользователей, контакты и поиск по username;
3. личные чаты, группы и каналы;
4. роли владельца и администраторов;
5. хранение сообщений, реакций, закрепов и статусов прочтения;
6. загрузку файлов;
7. WebSocket или Server-Sent Events для доставки сообщений;
8. WebRTC signaling для звонков;
9. rate limit, журнал безопасности и резервное копирование;
10. HTTPS и корректный CORS для GitHub Pages.

