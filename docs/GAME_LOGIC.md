# Игровая логика v2

Этот документ описывает независимый событийный движок игры «До пятницы». Текущий интерфейс понедельника пока продолжает работать через `src/app.js`; новый движок подготовлен отдельно, чтобы его можно было подключать по приложениям без переписывания сюжета в обработчиках интерфейса.

## Зачем нужен отдельный движок

Первая версия напрямую связывает кнопки интерфейса с последствиями. Это удобно для прототипа понедельника, но плохо масштабируется на пять дней. В версии 2:

- действие описывается данными;
- условие доступности описывается данными;
- последствия действия описываются данными;
- письма и сообщения появляются по времени и условиям;
- выбор понедельника может открыть или изменить событие вторника;
- настоящая причина пятничного разговора выбирается в начале прохождения и скрыта от игрока;
- концовка определяется общим состоянием, а не одной последней кнопкой.

## Файлы

- `src/engine.js` — универсальный движок без зависимости от DOM.
- `src/story-v2.js` — сюжет, действия, события, пять дней и концовки.
- `src/state-migration.js` — перенос решений из первого сохранения понедельника.
- `tests/engine.test.js` — тесты ключевых правил без сторонних библиотек.

## Скрытая правда прохождения

При создании новой игры движок выбирает один сценарий:

1. увольняют Илью;
2. увольняют молодого сотрудника;
3. сокращают весь отдел;
4. разговор относился к подрядчику.

Один и тот же `seed` всегда даёт один и тот же сценарий. Это позволит воспроизводить баги и конкретные прохождения, не показывая игроку правду заранее.

## Основное состояние

Движок хранит:

- текущий день и время;
- скрытый сценарий правды;
- качество работы;
- подозрение службы безопасности;
- собранные доказательства;
- тревогу;
- уровень доступа;
- лояльность;
- побочный ущерб коллегам;
- доверие отдельных персонажей;
- флаги сюжетных решений;
- доступы и найденные предметы;
- выполненные действия;
- доставленные и запланированные события;
- пропущенные обязательные задачи;
- журнал прохождения.

Игрок не должен видеть эти числа напрямую.

## Формат условий

Примеры:

```js
{ flag: "toldFriend" }
{ notFlag: "tamperedLogs" }
{ actionDone: "mon-invoice-fix" }
{ statGte: ["evidence", 2] }
{ trustGte: ["admin", 1] }
{ truthIs: "contractor" }
{ all: [{ hasItem: "payment-list" }, { statGte: ["access", 2] }] }
{ any: [{ flag: "projectFinished" }, { flag: "casePrepared" }] }
```

## Формат последствий

```js
{
  stats: { work: 2, suspicion: 1 },
  trust: { accountant: 1 },
  setFlags: { invoiceFixed: true },
  addItems: ["invoice-copy"],
  addAccess: ["finance-read"],
  schedule: [{ eventId: "tue-accountant-request", dayIndex: 1, minute: 590 }]
}
```

## Переход между днями

`endDay()`:

1. проверяет обязательные задачи дня;
2. применяет штрафы за пропуски;
3. записывает итог дня в журнал;
4. переводит игру на следующий день;
5. запускает утренние события;
6. в пятницу выбирает концовку.

## Подготовленные сюжетные узлы

### Понедельник

- правильная или ошибочная версия отчёта;
- исправление счёта или превращение его в компромат;
- просмотр вакансии;
- запрос доступа к папке руководства;
- признание другу.

### Вторник

- последствия работы со счётом;
- вопрос системного администратора;
- проверка пропусков;
- доступ к финансовым документам;
- отложенный клиент.

### Среда

- запрос службы безопасности;
- честное объяснение, удаление журнала или подстава друга;
- временное окно доступа к HR;
- кадровый приказ без фамилии.

### Четверг

- завершение полезного проекта;
- подготовка компромата;
- заявление по собственному желанию;
- попытка подставить начальника.

### Пятница

- спокойный разговор;
- демонстрация результатов;
- шантаж;
- уход по собственному желанию;
- выбор концовки с учётом всей недели.

## Миграция сохранения

`state-migration.js` умеет перенести из первой версии:

- скрытые показатели понедельника;
- доверие коллег;
- выбранные варианты задач;
- просмотр вакансии;
- запрос закрытого доступа;
- разговор с Димой;
- скопированные файлы.

Миграция пока не запускается автоматически. Она будет включена одновременно с переходом интерфейса на движок v2, чтобы текущий прототип продолжал работать без изменения поведения.

## Запуск тестов

```bash
node tests/engine.test.js
```

Тесты проверяют детерминированный сценарий, одноразовые действия, события по времени, последствия между днями, штрафы за пропущенные задачи, видимость разблокированного контента, миграцию сохранения и выбор концовок.

## Следующая интеграция

Следующий технический шаг — адаптер между `src/app.js` и `src/engine.js`. Интерфейс будет запрашивать у движка доступные действия и контент, а не изменять скрытые показатели самостоятельно. Это позволит добавить вторник без дублирования окон Проводника, Почты, «Связи», Задач и Терминала.
