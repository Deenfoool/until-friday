# Архитектура игры

## Единый игровой рантайм

`src/runtime-engine.js` является единственным модулем, которому разрешено заменять `UntilFridayEngine.createEngine`.

Он последовательно выполняет:

1. восстановление и нормализацию сохранения;
2. создание базового экземпляра движка;
3. проверку взаимоисключающих решений;
4. проверку дневного лимита фокуса;
5. проверку оставшегося рабочего времени;
6. атомарный запуск рабочего дня;
7. атомарное служебное изменение состояния;
8. выполнение сюжетного действия;
9. атомарный ход игрового времени;
10. доставку отложенных последствий;
11. атомарный переход между днями;
12. запись сохранения или полный откат;
13. публикацию события `until-friday-state-change`.

Изменять состояние разрешено только через методы активного экземпляра:

- `startDay()`;
- `updateState()`;
- `applyAction()`;
- `advanceTime()`;
- `endDay()`;
- `flushPendingConsequences()`.

Каждый из этих методов либо записывает полное новое состояние, либо восстанавливает состояние до вызова. Частично выполненных действий, времени, запуска дня, служебных флагов или переходов быть не должно.

Модули `rules-extension.js`, `integrity-fixes.js`, `story-consistency-fixes.js` и `time-boundary-guard.js` содержат правила и чистые вспомогательные функции. Они не переопределяют фабрику движка и не хранят собственный экземпляр.

`app-v2.js`, `passive-clock.js`, `day-transition-guard.js`, `day-end-control.js`, `terminal-sync.js`, `friday-clock-guard.js` и `ui-runtime-guards.js` получают активный движок только через:

```js
UntilFridayRuntimeEngine.getEngine()
```

Удалённый `persistent-engine-guard.js` не должен возвращаться. Также запрещены цепочки запасного доступа через часы или контроллер перехода.

## Владение сохранением

Запись ключа `until-friday-save-v2` принадлежит `runtime-engine.js`.

`app-v2.js` может прочитать сохранение при загрузке и вызвать ручное сохранение через `UntilFridayRuntimeEngine.persist()`, но не пишет engine-save напрямую.

UI-модули не должны:

- повторно сохранять результат успешного действия;
- самостоятельно откатывать движок;
- записывать отдельно прошедшие минуты;
- повторно сохранять уже выполненный переход;
- сохранять запуск рабочего дня отдельно;
- менять сюжетные флаги через собственную копию состояния;
- держать отдельную долгоживущую копию состояния как источник истины.

`workflow-extension.js` использует отдельное хранилище файлов и не считается частью engine-state.

## События состояния и интерфейса

После успешной записи рантайм отправляет:

```text
until-friday-state-change
```

В `event.detail` передаются:

- полное подтверждённое состояние;
- причина изменения;
- связанные события;
- идентификатор действия или количество прошедших минут, когда применимо.

Основное приложение после отрисовки окна отправляет:

```text
until-friday-ui-render
```

В `event.detail` передаются идентификатор приложения и элемент окна. Расширения реагируют на законченный цикл отрисовки вместо постоянного поиска случайных изменений DOM.

`return-from-vacation.js`, `day-end-control.js` и `ui-runtime-guards.js` работают только через lifecycle-события, взаимодействия пользователя и изменение размера окна. Эти системные модули не создают `MutationObserver`.

Статический HTML содержит нейтральный профиль `Сотрудник`. После входа профильный модуль подставляет имя, инициалы и терминальный логин игрока. Старые сюжетные формы прежнего технического имени заменяются после готовой отрисовки окна, поэтому они не появляются в интерфейсе и финале.

## Единый DOM-наблюдатель

`src/ui-observer-hub.js` сохраняет совместимость со старыми мини-играми, которые ещё вызывают `new MutationObserver(...)`, но создаёт только один нативный наблюдатель браузера.

Каждый старый модуль регистрируется как виртуальный подписчик. Записи фильтруются по его `target` и `options`, после чего callbacks выполняются пакетно один раз за кадр.

Это предотвращает:

- конкуренцию нескольких нативных наблюдателей;
- каскадные циклы микрозадач;
- многократную обработку одной перерисовки в пределах кадра;
- расхождение разных модулей по времени обновления DOM.

Новые системные модули не должны добавлять наблюдатели. Хаб остаётся временным слоем совместимости для старых интерактивных расширений.

## Достижимость сюжетных веток

Условия действий должны соответствовать ресурсам, которые реально можно получить в предыдущие дни.

Например, ветка жалобы на начальника требует:

- сохранённый список платежей;
- уровень служебного доступа `1`.

Уровень `1` выдаётся событием бухгалтера после исправления счёта. Прежнее требование уровня `2` делало ветку недостижимой и было удалено через `story-consistency-fixes.js`.

## Правила для новых модулей

- Не переопределять `UntilFridayEngine.createEngine`.
- Не создавать альтернативный `getEngine()` вне `UntilFridayRuntimeEngine`.
- Не обращаться к движку через `PassiveClock` или `DayTransitionGuard`.
- Не писать `until-friday-save-v2` из UI-модуля.
- Не хранить отдельную долгоживущую копию игрового состояния.
- Реагировать на `until-friday-state-change`, когда требуется обновление по состоянию.
- Реагировать на `until-friday-ui-render`, когда требуется обработать уже построенное окно.
- Не добавлять `MutationObserver` в новый системный UI-код.
- Старые мини-игры могут временно использовать наблюдатель только через общий хаб.
- Все сюжетные изменения выполнять через методы общего рантайма.
- Новая крупная ветка должна быть добавлена в полную пятидневную симуляцию.

## Регрессии

`tests/runtime-architecture.test.js` проверяет, что:

- фабрика движка заменяется ровно один раз;
- helper-модули не создают обёртки;
- удалённый persistence-фасад не существует;
- в `src/` нет запасных способов получить движок;
- несколько виртуальных наблюдателей используют один нативный наблюдатель;
- отключённые подписчики перестают получать записи.

`tests/app-runtime-ownership.test.js` проверяет, что основное приложение:

- не пишет engine-save напрямую;
- не сохраняет повторно действия, время и переходы;
- использует атомарное обновление пролога;
- публикует события состояния и отрисовки.

`tests/event-driven-ui.test.js` проверяет, что:

- системные UI-модули не наблюдают весь DOM;
- профиль в исходном HTML нейтрален;
- имя, инициалы и логин персонализируются через lifecycle-события;
- устаревшие карточки завершения дня удаляются.

`tests/persistence-guards.test.js` проверяет атомарный откат:

- запуска рабочего дня;
- служебного изменения состояния;
- сюжетного действия;
- хода времени;
- перехода на следующий день.

`tests/full-playthroughs.test.js` создаёт отдельный движок для каждого маршрута и проходит все пять дней через обычные команды рантайма:

- честная работа и презентация проекта;
- расследование, досье и предъявление материалов;
- вмешательство в журнал и жалоба на начальника;
- добровольное заявление.

Каждый маршрут обязан сохранить все промежуточные дни, открыть встречу в 17:00 и получить конкретную концовку без резервного `ordinary-friday`.
