# Архитектура игры

## Единый игровой рантайм

`src/runtime-engine.js` является единственным модулем, которому разрешено заменять `UntilFridayEngine.createEngine`.

Он последовательно выполняет:

1. восстановление и нормализацию сохранения;
2. создание базового экземпляра движка;
3. проверку взаимоисключающих решений;
4. проверку дневного лимита фокуса;
5. проверку оставшегося рабочего времени;
6. выполнение действия;
7. атомарную запись сохранения или полный откат;
8. атомарный ход игрового времени;
9. доставку отложенных последствий;
10. атомарный переход между днями;
11. публикацию события `until-friday-state-change`.

После запуска рабочего сеанса изменять состояние разрешено только через методы активного экземпляра:

- `applyAction()`;
- `advanceTime()`;
- `endDay()`;
- `flushPendingConsequences()`.

Каждый из этих методов либо записывает полное новое состояние, либо восстанавливает состояние до вызова. Частично выполненных действий, времени или переходов быть не должно.

Модули `rules-extension.js`, `integrity-fixes.js` и `time-boundary-guard.js` содержат только правила и чистые вспомогательные функции. Они не переопределяют фабрику движка и не хранят собственный экземпляр.

`passive-clock.js`, `day-transition-guard.js`, `day-end-control.js`, `terminal-sync.js`, `friday-clock-guard.js` и `ui-runtime-guards.js` получают активный движок только через:

```js
UntilFridayRuntimeEngine.getEngine()
```

Удалённый `persistent-engine-guard.js` не должен возвращаться. Также запрещены цепочки запасного доступа через часы или контроллер перехода.

## Владение сохранением

Запись ключа `until-friday-save-v2` принадлежит `runtime-engine.js`.

UI-модули не должны:

- повторно сохранять результат успешного действия;
- самостоятельно откатывать движок;
- записывать отдельно прошедшие минуты;
- повторно сохранять уже выполненный переход;
- держать собственную копию состояния как источник истины.

`workflow-extension.js` использует отдельное хранилище файлов и не считается частью engine-state.

Начальный запуск дня пока дополнительно сохраняется основным приложением для совместимости со старым загрузочным потоком. Все дальнейшие игровые изменения принадлежат единому рантайму.

## Событие состояния

После успешной записи рантайм отправляет:

```text
until-friday-state-change
```

В `event.detail` передаются:

- полное подтверждённое состояние;
- причина изменения;
- связанные события;
- идентификатор действия или количество прошедших минут, когда применимо.

UI должен реагировать на это событие, а не пытаться угадывать изменение состояния по DOM.

## Единый DOM-наблюдатель

`src/ui-observer-hub.js` сохраняет совместимость с существующими вызовами `new MutationObserver(...)`, но создаёт только один нативный наблюдатель браузера.

Каждый модуль регистрируется как виртуальный подписчик. Записи фильтруются по его `target` и `options`, после чего callbacks выполняются пакетно один раз за кадр.

Это предотвращает:

- конкуренцию нескольких нативных наблюдателей;
- каскадные циклы микрозадач;
- многократную обработку одной перерисовки в пределах кадра;
- расхождение разных модулей по времени обновления DOM.

Системные UI-модули дополнительно подписываются на `until-friday-state-change`, поэтому доступность кнопок и счётчики обновляются сразу после подтверждённой команды.

## Правила для новых модулей

- Не переопределять `UntilFridayEngine.createEngine`.
- Не создавать альтернативный `getEngine()` вне `UntilFridayRuntimeEngine`.
- Не обращаться к движку через `PassiveClock` или `DayTransitionGuard`.
- Не писать `until-friday-save-v2` из UI-модуля.
- Не хранить отдельную долгоживущую копию игрового состояния.
- Реагировать на `until-friday-state-change`, когда требуется обновление по состоянию.
- Допускается использовать `MutationObserver`: общий хаб автоматически превратит его в виртуальную подписку.
- Не создавать собственный нативный наблюдатель через сохранённую ссылку на браузерный `MutationObserver`.
- Все сюжетные действия выполнять через методы общего рантайма.

## Регрессии

`tests/runtime-architecture.test.js` проверяет, что:

- фабрика движка заменяется ровно один раз;
- helper-модули не создают обёртки;
- удалённый persistence-фасад не существует;
- в `src/` нет запасных способов получить движок;
- несколько виртуальных наблюдателей используют один нативный наблюдатель;
- отключённые подписчики перестают получать записи.

`tests/persistence-guards.test.js` проверяет атомарный откат:

- сюжетного действия;
- хода времени;
- перехода на следующий день.
